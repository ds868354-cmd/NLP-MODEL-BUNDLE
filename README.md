### Deploying (Docker / Kubernetes / CI)

1. **Credentials and data stay out of git and out of the image.** `.gitignore` and `.dockerignore` exclude `api_keys.json`, `pipeline_run_summary.json`, `notebook_data_sample.csv` and `validation_report*.csv` (real rows, and often > 50 MiB). The Dockerfile does `COPY . ./` and the default-deny `.dockerignore` decides what enters the image: the model / recipe `*.json` files do, credentials, run summaries and data samples never do.
2. **Local container** (the image runs as uid 10001, so the mounted key file must be readable by it):
```bash
docker build -t automl-model .
chmod 644 api_keys.json
docker run -p 8000:8000 -v "$PWD/api_keys.json:/secrets/api_keys.json:ro" -e API_KEYS_PATH=/secrets/api_keys.json automl-model
```
3. **Kubernetes:** publish the keys as a Secret, render the image reference, apply (the manifest creates a ConfigMap, the Deployment with a read-only root filesystem and non-root user, the Service, a PodDisruptionBudget and a HorizontalPodAutoscaler):
```bash
kubectl create secret generic dataset-nlp-api-keys --from-file=api_keys.json=./api_keys.json
kubectl apply -f k8s.yaml
```
   `k8s.yaml` always contains a valid image name (the registry image when `--image_owner` / `IMAGE_OWNER` was set, otherwise the local `<app>:latest` with `imagePullPolicy: IfNotPresent` -- build it with `docker build -t <app>:latest .`). To deploy the image CI pushed, run `kubectl set image deployment/<app> <app>=<registry>/<owner>/<name>:<tag>`.
   Optional: `kubectl apply -f k8s-networkpolicy.yaml` restricts the pods' network (ingress only from the `ingress-nginx` namespace and the pods' own namespace -- change the label value if your ingress controller lives elsewhere; it only takes effect on clusters whose network plugin enforces NetworkPolicy). `kubectl apply -f k8s-ingress.yaml` adds TLS (create the `<name>-tls` secret and set the host first), a body-size cap and a cluster-wide rate limit at the edge. Pin the base image by digest with `docker build --build-arg PYTHON_IMAGE=python:3.11-slim@sha256:<digest> .`.
4. **CI (`.github/workflows/ci.yml`):** credential-file check -> Kubernetes manifest validation -> `tests/` -> no-pickle guardrail -> lint + Hadolint -> image build + Trivy vulnerability scan (pull requests build and scan only) -> push + rendered manifest (main branch). `.github/dependabot.yml` keeps the action / base-image / pip pins current.
5. **Good to know:** the in-app rate limit is per pod and per API key (2 replicas = twice the limit) -- the Ingress limit is the cluster-wide one; only keys whose `role` is in `PREDICT_ROLES` may score (`create_api_key.py` now issues `reader` keys by default); `/docs` is closed when `APP_ENV=production`; `/health` is unauthenticated and shows artifact NAMES only, answering 503 until the model, its recipe and (binary tabular / ANN) the decision threshold are all loaded AND -- when authentication is required -- a key store (mounted file or `API_KEYS_JSON`) exists (otherwise the app logs `Authentication enabled but no valid key-store or env found at runtime.`, keeps running and reports `auth_ready=false`); `/healthz` is the always-200 liveness probe. Latency and PSI-drift monitoring run in a FastAPI BackgroundTask after the response (never inside it). The Docker image is built with ONE `COPY . ./` filtered by the default-deny `.dockerignore` (safe formats only, no pickle / joblib, no credentials). The zip contains `api_keys.json` (hashes only) unless you set `AUTOML_EXCLUDE_API_KEYS=1` when building -- treat the zip as a secret either way.
